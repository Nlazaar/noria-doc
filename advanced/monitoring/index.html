    Dashboard de monitoring

    Noria embarque un dashboard web qui s'ouvre dans le navigateur et affiche l'état du pipeline en temps réel.

    Il est basé sur FastAPI + HTMX — léger, sans dépendance frontend, accessible à http://127.0.0.1:7070.

    Accéder au dashboard

    Une fois le serveur démarré (voir ci-dessous), ouvrir dans le navigateur :

    http://127.0.0.1:7070

    Le port par défaut est 7070. Si tu as changé le port dans noria.yml ou via --port, utiliser ce port à la place.

    Lancer le dashboard

    Avec un run en cours

    noria run --monitor

    Le dashboard démarre automatiquement en arrière-plan au début du run. Ouvrir http://127.0.0.1:7070 dans le navigateur pendant ou après l'exécution — il se met à jour toutes les 3 secondes.

    En standalone (hors run)

    noria monitor                        # démarre le serveur, URL affichée dans le terminal
noria monitor --port 8080            # port custom → http://127.0.0.1:8080
noria monitor --open                 # démarre + ouvre le navigateur automatiquement
noria monitor --port 8080 --open     # les deux

    Utile pour consulter l'historique des runs passés sans relancer le pipeline.

    Tip

    L'URL est toujours affichée dans le terminal au démarrage : 

    Dashboard disponible → http://127.0.0.1:7070

    Ce qu'affiche le dashboard

    Le dashboard est organisé en 4 onglets :

    Onglet Runs

    Bannière live rafraîchie toutes les 3 secondes :

    • En cours — pipeline actif, jobs en cours listés
    • Idle — aucune exécution active

    Tableau des 30 derniers runs avec :

    Colonne Description
    Run ID Identifiant unique du run
    Statut OK / KO / Running / Aborted
    Durée Temps total d'exécution
    Jobs Nombre de jobs exécutés
    Lignes Total de lignes écrites
    Démarré Horodatage de début

    Cliquer sur un run affiche le détail job par job :

    • Statut individuel (OK / KO / Skipped / Aborted)
    • Durée par job
    • Lignes écrites
    • Message d'erreur complet si échec

    Un bouton Déclencher un run lance le pipeline en arrière-plan depuis le navigateur.

    Onglet Jobs

    Vue d'ensemble de tous les jobs du pipeline :

    • Nom, type, table cible, tags
    • Dernier statut connu et horodatage
    • Lien vers le détail du dernier run

    Onglet Lignage

    Graphe Mermaid.js interactif du pipeline :

    • Nœuds = jobs, arêtes = dépendances (after:)
    • Sources et cibles de tables annotées
    • Mise à jour automatique après chaque run

    Onglet Impact

    Analyse d'impact bidirectionnelle interactive :

    • Champ de recherche par table ou pipeline
    • Résultats en temps réel (HTMX)
    • Clic sur une table → ses pipelines amont/aval
    • Clic sur un pipeline → ses tables sources et cibles

    Activer automatiquement au démarrage

    Pour que le dashboard s'ouvre à chaque noria run sans le flag --monitor :

    # noria.yml
monitoring:
  enabled: true
  port: 7070
  auto_open: false   # true = ouvre le navigateur automatiquement
    Champ Défaut Description
    enabled true Démarrer le dashboard avec noria run
    port 7070 Port d'écoute
    auto_open false Ouvrir le navigateur automatiquement

    Note

    enabled: true démarre le serveur en arrière-plan mais n'ouvre pas le navigateur sauf si auto_open: true.

    Accès depuis une autre machine

    Par défaut le dashboard écoute sur 127.0.0.1 (loopback). Pour l'exposer sur le réseau local :

    noria monitor --host 0.0.0.0 --port 7070

    Sécurité

    Le dashboard n'a pas d'authentification. Ne pas l'exposer sur Internet sans proxy sécurisé.

    API REST

    Le dashboard expose une API REST complète — voir la Référence API pour la documentation complète.

    Endpoints principaux :

    GET  /api/v1/health                          → santé du serveur
GET  /api/v1/runs                            → 50 derniers runs
GET  /api/v1/runs/{run_id}                   → détail d'un run
GET  /api/v1/jobs                            → liste des jobs
GET  /api/v1/lineage                         → lignage du pipeline
GET  /api/v1/impact/pipeline/{nom}           → tables d'un pipeline
GET  /api/v1/impact/table/{schema.table}     → pipelines d'une table
POST /api/v1/trigger                         → déclencher un run

    Exemple :

    curl http://127.0.0.1:7070/api/v1/runs | jq '.[0]'

    {
  "run_id": "abc123",
  "status": "finished_ok",
  "started_at": "2026-09-25T08:30:00",
  "duration_s": 4.2,
  "jobs_ok": 3,
  "jobs_ko": 0,
  "rows_written": 12450
}
