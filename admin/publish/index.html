    Publier une nouvelle version de Noria sur PyPI

    Ce guide est destiné au mainteneur du package. Il décrit les étapes complètes pour modifier le code, builder le package et le publier sur PyPI.

    Prérequis (une seule fois)

    1. Compte PyPI

    Le package noria est enregistré sur pypi.org sous le compte Noria Contributors.
    Tu dois avoir accès à ce compte pour publier.

    2. Token API PyPI

    Sur PyPI : Account settings → API tokens → Add API token

    • Scope : limiter au projet noria
    • Copier le token (commence par pypi-)

    3. Configurer uv pour utiliser le token

    # Stocker le token dans la config uv (une seule fois sur ta machine)
uv publish --token pypi-XXXXXXXXXXXXXXXX

    Ou créer un fichier ~/.pypirc :

    [pypi]
  username = __token__
  password = pypi-XXXXXXXXXXXXXXXX

    Workflow — publier une nouvelle version

    Étape 1 — Modifier le code

    Faire les modifications nécessaires dans src/noria/.
    Lancer les tests pour vérifier que tout passe :

    uv run python -m pytest

    Les 378 tests doivent passer à 100% avant de publier.

    Étape 2 — Bumper la version

    La version est définie dans pyproject.toml, ligne :

    version = "0.1.0"

    Suivre le versionnage sémantique :

    Type de changement Exemple
    Correctif (bug fix) 0.1.0 → 0.1.1
    Nouvelle fonctionnalité (rétrocompatible) 0.1.0 → 0.2.0
    Rupture de compatibilité 0.1.0 → 1.0.0

    Modifier la version dans pyproject.toml :

    version = "0.2.0"   # ← nouvelle version

    Étape 3 — Committer et taguer

    # Committer la nouvelle version
git add pyproject.toml
git commit -m "chore: bump version to 0.2.0"

# Poser un tag git
git tag -a v0.2.0 -m "v0.2.0 — description courte des changements"

# Pousser sur GitHub
git push origin main
git push origin v0.2.0

    Étape 4 — Builder le package

    # Nettoyer les anciens builds
rm -rf dist/

# Construire le wheel et le source distribution
uv build

    Résultat attendu dans dist/ :

    dist/
  noria-0.2.0-py3-none-any.whl
  noria-0.2.0.tar.gz

    Étape 5 — Publier sur PyPI

    uv publish

    Si le token n'est pas configuré globalement :

    uv publish --token pypi-XXXXXXXXXXXXXXXX

    Étape 6 — Vérifier la publication

    # Attendre ~1 minute puis vérifier
pip index versions noria

    Ou vérifier sur pypi.org/project/noria.

    Étape 7 — Tester l'installation depuis PyPI

    # Dans un environnement vierge
uv run --with noria noria --version

    En cas d'erreur

    "File already exists"

    PyPI n'accepte pas l'écrasement d'une version existante.
    Il faut obligatoirement bumper la version dans pyproject.toml et rebuilder.

    "Invalid token"

    Vérifier que le token commence bien par pypi- et qu'il a le scope du projet noria.

    Les tests échouent avant la publication

    Ne jamais publier avec des tests en échec. Corriger le code, puis recommencer depuis l'étape 1.

    Résumé rapide

    # 1. Tests
uv run python -m pytest

# 2. Bumper la version dans pyproject.toml

# 3. Git
git add pyproject.toml
git commit -m "chore: bump version to X.Y.Z"
git tag -a vX.Y.Z -m "vX.Y.Z — ..."
git push origin main && git push origin vX.Y.Z

# 4. Build + publish
rm -rf dist/
uv build
uv publish
