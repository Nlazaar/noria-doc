    Référence CLI

    noria run

    Lance le pipeline complet ou un sous-ensemble de jobs.

    noria run [OPTIONS]
    Option Description Défaut
    --job / -j Job(s) spécifiques à exécuter tous
    --env / -e Environnement (envs/{env}.yml) aucun
    --dry-run Compiler le SQL sans exécuter false
    --workers / -w Threads parallèles max 4
    --only-tags Filtre par tag(s) aucun
    --continue-on-error Ne pas s'arrêter sur erreur false
    --param k=v Paramètre CLI (surcharge noria.yml) aucun
    --params-file Fichier YAML de paramètres aucun
    --log-file Chemin du fichier de log aucun
    --monitor Démarrer le dashboard de monitoring false
    --verbose / -v Logs DEBUG détaillés false 
    noria run                              # tout exécuter (env défaut)
noria run --env prod                   # environnement prod
noria run --job clients                # un seul job
noria run --job clients --job rapport  # plusieurs jobs
noria run --only-tags daily            # jobs tagués daily
noria run --dry-run                    # SQL sans exécution
noria run --param schema=staging       # surcharge un paramètre

    noria run-job

    Exécute un seul job sans ses dépendances.

    noria run-job <nom_du_job> [--env prod] [--dry-run]

    noria jobs

    Liste tous les jobs du pipeline et leurs dépendances.

    noria jobs [--env prod]

    noria compile

    Compile le SQL Jinja2 sans exécuter — utile pour vérifier le SQL généré.

    noria compile [--job nom] [--env prod] [--output fichier.sql]

    noria preview

    Affiche les premières lignes d'un job sans écrire en base.

    noria preview <nom_du_job> [--limit 20] [--env prod]

    noria validate

    Valide la configuration et le DAG sans connexion base de données.

    noria validate [--env prod]

    noria add

    Ajoute un nouveau job à noria.yml de manière interactive.

    noria add <nom_du_job> [--sql sql/mon_job.sql] [--target main.ma_table] [--after autre_job]

    noria dag

    Génère la cartographie visuelle du DAG.

    noria dag [--format html|mermaid|ascii] [--output fichier]
    Format Description
    html Page HTML avec Mermaid (défaut, s'ouvre dans le navigateur)
    mermaid Texte Mermaid brut (pour README, GitLab, Notion)
    ascii Arbre ASCII dans le terminal

    noria status

    Affiche l'historique des exécutions.

    noria status [--limit 20]

    noria monitor

    Démarre le dashboard web de monitoring.

    noria monitor [--port 7070] [--open/--no-open]

    noria docs

    Génère une page HTML de documentation du pipeline (jobs, SQL, dépendances).

    noria docs [--output docs/pipeline.html]

    noria watch

    Mode développeur : relance le pipeline automatiquement à chaque modification d'un fichier SQL ou YAML.

    noria watch  # nécessite: pip install "noria[watch]"

    noria init

    Crée un nouveau projet Noria avec la structure de fichiers complète.

    noria init mon_pipeline [--dir /chemin/parent]

    Utilisation avec un ordonnanceur

    Noria est conçu pour s'intégrer sans friction dans Jenkins, Airflow, cron ou tout autre ordonnanceur.

    # Jenkins / script shell
noria run --env prod --project /pipelines/mon_pipeline --log-file logs/run.log

# Airflow (BashOperator)
noria run --env prod --only-tags daily --continue-on-error

# Cron (crontab)
0 6 * * * cd /pipelines/mon_pipeline && noria run --env prod

    Les variables de connexion sensibles passent par des variables d'environnement résolues dans envs/prod.yml :

    # envs/prod.yml
database:
  host: ${DB_HOST}
  password: ${DB_PASSWORD}
