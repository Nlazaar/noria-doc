    Mapping des schémas — schemas:

    Le bloc schemas: permet d'écrire du SQL non qualifié — sans préfixe schéma — et de laisser Noria qualifier automatiquement les noms de tables au moment de la compilation.

    -- Ce que vous écrivez
SELECT * FROM raw_orders o
JOIN dim_client d ON o.client_id = d.id

-- Ce que Noria exécute
SELECT * FROM staging.raw_orders o
JOIN dwh.dim_client d ON o.client_id = d.id

    Pourquoi schemas: ?

    Sans schemas:, deux approches co-existent dans Noria :

    Approche Syntaxe SQL Avantage Limite
    Qualifié explicite FROM staging.raw_orders Clair SQL couplé au schéma — change si on migre
    catalog: + {{ source() }} FROM {{ source('raw_orders') }} Découplé Syntaxe Jinja2 à apprendre
    schemas: FROM raw_orders SQL pur, non qualifié Toutes les tables doivent être déclarées

    schemas: est idéal quand :

    • vous migrez du code SAS (où les LIBNAME qualifient implicitement), Alteryx, ou PowerCenter
    • votre équipe SQL préfère écrire du SQL standard sans {{ }} Jinja2
    • vous voulez changer le routage schéma → table en un seul endroit

    Syntaxe de base

    # noria.yml
schemas:
  staging:
    - raw_orders
    - raw_clients
    - raw_products
  dwh:
    - dim_client
    - dim_produit
    - fact_ventes

    Les clés sont les noms de schéma. Chaque entrée est le nom de table tel qu'il apparaîtra dans votre SQL.

    -- SQL que vous écrivez (non qualifié)
SELECT
    o.commande_id,
    c.nom_client,
    SUM(o.montant) AS ca
FROM raw_orders o
JOIN dim_client c ON o.client_id = c.id
GROUP BY o.commande_id, c.nom_client

    -- SQL exécuté par Noria (après compilation)
SELECT
    o.commande_id,
    c.nom_client,
    SUM(o.montant) AS ca
FROM staging.raw_orders o
JOIN dwh.dim_client c ON o.client_id = c.id
GROUP BY o.commande_id, c.nom_client

    Désambiguïsation par alias

    Si une même table existe dans plusieurs schémas, une entrée sans alias produirait une erreur de configuration au démarrage. Utilisez la syntaxe table as alias pour différencier :

    schemas:
  dwh:
    - dim_client                    # → SQL : dim_client → dwh.dim_client
  edd:
    - "dim_client as edd_dim"       # → SQL : edd_dim    → edd.dim_client

    -- Chaque nom SQL est unique → aucune ambiguïté
SELECT d.*, e.score_risque
FROM dim_client d
JOIN edd_dim e ON d.id = e.id

    -- Compilé en :
SELECT d.*, e.score_risque
FROM dwh.dim_client d
JOIN edd.dim_client e ON d.id = e.id

    Alias obligatoire en cas de doublon

    Si dim_client apparaît dans deux schémas sans alias, Noria lève une ConfigError dès le chargement de la configuration — avant toute exécution.

    ConfigError: Duplicate table identifier 'dim_client' in schemas: map
('dwh' and 'edd'). Use 'table_name as alias' to disambiguate.

    Ce que Noria qualifie — et ce qu'il laisse intact

    La qualification s'applique aux tables référencées après les mots-clés SQL : FROM, JOIN, UPDATE, INTO.

    Ignoré automatiquement

    Cas Exemple Comportement
    Déjà qualifié FROM staging.raw_orders Inchangé
    Fonction tabulaire FROM read_csv('file.csv') Inchangé
    CTE WITH cte AS (...) SELECT * FROM cte cte non qualifié
    Tables internes Noria FROM _noria_job_s1 Inchangé (stages)
    Littéraux SQL SELECT 'FROM raw_orders' AS note Inchangé
    Commentaires -- FROM raw_orders Inchangé

    Tables inconnues → erreur

    Si schemas: est défini et qu'une table non qualifiée n'est pas dans le mapping, Noria lève une SchemaResolutionError à la compilation :

    SchemaResolutionError: Table 'unknown_table' not found in schemas: map.
Add it under the correct schema in noria.yml
or use {{ source('...') }} for catalog entries.
Known tables: dim_client, edd_dim, raw_clients, raw_orders

    Compatibilité ascendante

    Si schemas: est absent du noria.yml, la qualification est désactivée — aucun SQL existant n'est modifié.

    Interaction avec catalog:

    schemas: et catalog: sont complémentaires et peuvent coexister dans le même projet :

    # catalog : sources externes (requêtes issues d'un autre système)
catalog:
  external_ref:
    schema: ext
    table: ref_pays
    description: "Référentiel pays — base externe"

# schemas : tables internes du pipeline
schemas:
  staging:
    - raw_orders
    - raw_clients
  dwh:
    - dim_client
    - fact_ventes

    -- Mélange catalog + schemas dans le même SQL
SELECT o.*, r.libelle_pays
FROM raw_orders o                        -- via schemas: → staging.raw_orders
JOIN {{ source('external_ref') }} r      -- via catalog:  → ext.ref_pays
  ON o.pays_code = r.code_pays
    catalog: schemas:
    Syntaxe SQL {{ source('id') }} FROM table_name
    SQL pur Non Oui
    Sources externes Idéal Possible
    Tables internes Possible Idéal
    Alias / renommage Via table: + id: Via table as alias

    Interaction avec stages:

    Dans un job multi-stages, schemas: s'applique à chaque stage indépendamment. Les tables temporaires _noria_* (références {{ prev }}) sont automatiquement ignorées.

    jobs:
  rapport:
    stages:
      - sql/01_extract.sql
      - sql/02_transform.sql
      - sql/03_enrich.sql
    target: dwh.rapport_mensuel
    write_mode: replace

    -- sql/01_extract.sql — raw_orders qualifié → staging.raw_orders
SELECT client_id, SUM(montant) AS total
FROM raw_orders
GROUP BY client_id

    -- sql/02_transform.sql — {{ prev }} = table interne _noria_rapport_s1 (inchangée)
SELECT *, total * 1.20 AS total_ttc
FROM {{ prev }}

    -- sql/03_enrich.sql — dim_client qualifié → dwh.dim_client ; {{ prev }} inchangé
SELECT p.*, c.segment
FROM {{ prev }} p
JOIN dim_client c ON p.client_id = c.id

    CTEs et sous-requêtes

    Les noms de CTE ne sont jamais qualifiés — Noria les détecte automatiquement grâce au pattern WITH nom AS ( :

    WITH commandes_actives AS (
    SELECT * FROM raw_orders WHERE statut = 'V'   -- raw_orders qualifié
),
clients_premium AS (
    SELECT * FROM dim_client WHERE segment = 'P'  -- dim_client qualifié
)
SELECT *
FROM commandes_actives c                          -- CTE → inchangé
JOIN clients_premium p ON c.client_id = p.id     -- CTE → inchangé

    Exemple complet

    # noria.yml
name: pipeline_commercial
database:
  dialect: duckdb
  database: .noria/data.db

schemas:
  staging:
    - raw_orders
    - raw_clients
    - raw_products
  dwh:
    - dim_client
    - dim_produit
    - fact_ventes
  reporting:
    - rapport_mensuel
    - rapport_clients

jobs:

  charger_clients:
    sql: sql/clients.sql
    target: dwh.dim_client
    write_mode: merge
    merge_key: [id]

  charger_commandes:
    sql: sql/commandes.sql
    target: dwh.fact_ventes
    write_mode: replace
    after: [charger_clients]

  rapport:
    stages:
      - sql/rapport/01_base.sql
      - sql/rapport/02_enrichi.sql
    target: reporting.rapport_mensuel
    write_mode: replace
    after: [charger_commandes]

    -- sql/clients.sql
SELECT id, nom, email, segment
FROM raw_clients
WHERE actif = true

    -- sql/commandes.sql
SELECT o.*, c.segment AS segment_client
FROM raw_orders o
JOIN dim_client c ON o.client_id = c.id
WHERE o.statut = 'V'

    -- sql/rapport/01_base.sql
SELECT
    EXTRACT(MONTH FROM date_commande) AS mois,
    segment_client,
    SUM(montant)                      AS ca_total,
    COUNT(*)                          AS nb_commandes
FROM fact_ventes
GROUP BY 1, 2

    -- sql/rapport/02_enrichi.sql
SELECT
    p.*,
    {{ current_timestamp() }} AS computed_at
FROM {{ prev }} p
ORDER BY mois, ca_total DESC

    Référence

    Syntaxe YAML

    schemas:
  nom_schema:
    - table_simple            # identifiant SQL = table_simple
    - "table as alias"        # identifiant SQL = alias → DB: nom_schema.table

    Règles

    Règle Détail
    Identifiant unique Un même nom SQL ne peut apparaître que dans un seul schéma (ou avec alias)
    Insensible à la casse Raw_Orders et raw_orders sont équivalents dans le mapping
    Priorité schemas: s'applique après Jinja2 — {{ params.x }} est résolu avant la qualification
    Sans schemas: Aucune modification — compatibilité totale avec les projets existants

    Erreurs possibles

    Erreur Cause Solution
    ConfigError: Duplicate table identifier Même nom dans deux schémas sans alias Ajouter as alias à l'une des deux entrées
    SchemaResolutionError: Table '...' not found Table non qualifiée absente du mapping Ajouter la table dans schemas: ou qualifier manuellement
