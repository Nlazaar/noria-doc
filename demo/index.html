    Démo complète — Boutique en ligne

    Ce pipeline démo illustre toutes les fonctionnalités Noria sur un cas concret de boutique en ligne. Aucune base de données externe n'est requise — les données sont générées synthétiquement par DuckDB.

    Source : examples/demo/ dans le dépôt.

    git clone https://github.com/Nlazaar/noria
cd noria/examples/demo
noria run

    Structure du projet

    examples/demo/
├── noria.yml                        # configuration complète
├── data/
│   ├── ref_pays.csv                 # référentiel ISO pays (seed CSV)
│   └── ref_statuts.csv              # codes statut commandes (seed CSV)
├── envs/
│   └── prod.yml                     # surcharge PostgreSQL pour la production
└── sql/
    ├── macros/utils.sql.j2          # macros Jinja2 utilisateur

    │   ├── raw_clients.sql          # 50 clients
    │   ├── raw_commandes.sql        # 500 commandes
    │   └── raw_produits.sql         # 20 produits
    ├── init/
    │   ├── calcul_params.sql        # compute_params → injecte date_max, seuil_ca
    │   └── ref_calendar.sql         # calendrier 2020-2030 (create_if_not_exists)
    ├── transform/
    │   ├── clients.sql              # enrichissement + pays
    │   ├── commandes.sql            # filtre + statuts (incremental)
    │   ├── produits.sql             # catalogue actifs (merge)

    noria.yml — configuration annotée

    name: demo_boutique
description: "Pipeline démo complet — illustre toutes les fonctionnalités Noria"
version: "1"

database:
  dialect: duckdb
  database: .noria/demo.db

params:
  schema: main
  annee: 2023
  seuil_ca: 100       # recalculé dynamiquement par calcul_params

# Sources externes — référencées via {{ source('id') }} dans le SQL
catalog:
  raw_clients:   { schema: main, table: raw_clients }
  raw_commandes: { schema: main, table: raw_commandes }
  raw_produits:  { schema: main, table: raw_produits }
  ref_pays: "main.ref_pays"

# Tables internes — SQL non qualifié, Noria qualifie automatiquement
schemas:
  main:
    - ref_statuts
    - clients
    - commandes
    - produits
    - dim_client
    - stats_mensuelles
    - kpi_global

    Les jobs, un par un

    1. Seeds — chargement de fichiers CSV

    seed_pays:
  type: seed
  seed_file: data/ref_pays.csv
  target: "{{ params.schema }}.ref_pays"
  tags: [init, reference]

    Les seeds chargent des fichiers plats (CSV, Parquet, JSON) directement en base. Aucun SQL à écrire.

    2. Données brutes — generate_series DuckDB

    raw_clients:
  sql: sql/raw/raw_clients.sql
  target: "{{ params.schema }}.raw_clients"
  write_mode: replace
  tags: [raw]

    -- sql/raw/raw_clients.sql — 50 clients synthétiques, aucune source externe
SELECT
    n                                           AS id_client,
    CASE n % 5
        WHEN 0 THEN 'Dupont'  WHEN 1 THEN 'Martin'
        WHEN 2 THEN 'Durand'  WHEN 3 THEN 'Bernard'
        ELSE 'Petit'
    END                                         AS nom,
    'client' || LPAD(n::VARCHAR, 3, '0') || '@demo.com' AS email,
    CASE n % 4
        WHEN 0 THEN 'IDF' WHEN 1 THEN 'ARA'
        WHEN 2 THEN 'OCC' ELSE 'HDF'
    END                                         AS region,
    DATE '2022-01-01' + INTERVAL (n * 13 % 730) DAY AS date_inscription
FROM generate_series(1, 50) t(n)

    3. compute_params — seuils dynamiques

    calcul_params:
  sql: sql/init/calcul_params.sql
  compute_params: true    # la 1re ligne du SELECT devient des {{ params }}
  after: [raw_commandes]

    -- sql/init/calcul_params.sql — retourne UNE ligne
-- Chaque colonne devient un paramètre dans tous les jobs after: [calcul_params]
SELECT
    MAX(date_commande)::VARCHAR   AS date_max,
    MIN(date_commande)::VARCHAR   AS date_min,
    ROUND(AVG(montant))::INTEGER  AS seuil_ca,
    COUNT(DISTINCT region)        AS nb_regions
FROM {{ source('raw_commandes') }}
WHERE statut <> 'annulé'

    Après ce job, {{ params.date_max }}, {{ params.seuil_ca }}, etc. sont disponibles dans tous les jobs dépendants.

    4. Transformations

    Clients — replace + catalog: + macros

    -- sql/transform/clients.sql
-- catalog: → {{ source('raw_clients') }}, {{ source('ref_pays') }}
-- schemas: → plus besoin de préfixe schéma
SELECT
    c.id_client,
    c.nom || ' ' || c.prenom       AS nom_complet,
    LOWER(c.email)                 AS email,
    c.region,
    p.libelle_pays,
    p.continent,
    'standard'                     AS segment,
    {{ current_timestamp() }}      AS updated_at
FROM {{ source('raw_clients') }} c
LEFT JOIN {{ source('ref_pays') }} p ON c.code_pays = p.code_pays

    Commandes — incremental

    commandes:
  write_mode: incremental
  incremental_key: date_commande   # seule la dernière partition est rechargée
  retry: 2
  retry_delay_s: 5
  timeout: 120
  after: [raw_commandes, calcul_params, seed_statuts]

    -- sql/transform/commandes.sql
-- schemas: qualifie ref_statuts → main.ref_statuts automatiquement
SELECT
    c.id_commande, c.date_commande, c.montant, c.region,
    s.libelle_statut,
    {{ current_timestamp() }}  AS updated_at
FROM {{ source('raw_commandes') }} c
LEFT JOIN ref_statuts s ON c.statut = s.code_statut
WHERE c.statut <> 'annulé'
  AND c.date_commande BETWEEN '{{ params.date_min | default("2023-01-01") }}'
                          AND '{{ params.date_max | default("2023-12-31") }}'

    Produits — merge

    produits:
  write_mode: merge
  merge_key: [id_produit]   # delete+insert sur la clé — les autres lignes restent

    Dimension client — scd2

    dim_client:
  write_mode: scd2
  scd2_key: [id_client]
  scd2_updated_at: date_maj

    Noria gère automatiquement _valid_from, _valid_to, _is_current.

    -- sql/transform/dim_client.sql
-- schemas: qualifie clients → main.clients
SELECT id_client, nom, prenom, email, ville, region, segment, date_maj
FROM clients

    Mise à jour des segments — update

    update_segments:
  write_mode: update
  update_key: [id_client]
  update_cols: [segment, segment_date]   # seules ces colonnes sont modifiées
  after: [stats_mensuelles, clients]

    -- sql/transform/update_segments.sql
-- {{ params.seuil_ca }} injecté par calcul_params
-- schemas: qualifie clients et commandes
SELECT
    c.id_client,
    CASE
        WHEN COALESCE(s.ca_total, 0) >= {{ params.seuil_ca | default(300) }} * 3 THEN 'premium'
        WHEN COALESCE(s.ca_total, 0) >= {{ params.seuil_ca | default(300) }}     THEN 'fidele'
        ELSE 'standard'
    END                          AS segment,
    {{ current_timestamp() }}    AS segment_date
FROM clients c
LEFT JOIN (
    SELECT id_client, ROUND(SUM(montant), 2) AS ca_total
    FROM commandes
    GROUP BY id_client
) s ON c.id_client = s.id_client

    5. Rapport multi-stages — 3 SQL chaînés

    stats_mensuelles:
  stages:
    - sql/report/01_agregation.sql
    - sql/report/02_enrichissement.sql
    - sql/report/03_formatage.sql
  target: "{{ params.schema }}.stats_mensuelles"
  write_mode: replace
  after: [commandes, clients]

    -- sql/report/01_agregation.sql — Stage 1
-- schemas: qualifie commandes → main.commandes
SELECT
    EXTRACT(YEAR  FROM date_commande)::INTEGER AS annee,
    EXTRACT(MONTH FROM date_commande)::INTEGER AS mois,
    region,
    COUNT(*)                                   AS nb_commandes,
    ROUND(SUM(montant), 2)                     AS ca_total,
    ROUND(AVG(montant), 2)                     AS panier_moyen
FROM commandes
WHERE EXTRACT(YEAR FROM date_commande) = {{ params.annee }}
GROUP BY 1, 2, 3

    -- sql/report/02_enrichissement.sql — Stage 2
-- {{ prev }} = table temporaire _noria_stats_mensuelles_s1 (gérée par Noria)
SELECT
    *,
    {{ running_total('ca_total', by='region', order_by='mois') }}  AS ca_cumul_region,
    {{ pct_of_total('ca_total', by='annee, mois') }}               AS pct_ca_mois
FROM {{ prev }}

    -- sql/report/03_formatage.sql — Stage 3 (final, écrit dans target)
SELECT
    annee, mois,
    annee::VARCHAR || '-' || LPAD(mois::VARCHAR, 2, '0')  AS periode,
    region, nb_commandes, ca_total, panier_moyen,
    ca_cumul_region, pct_ca_mois,
    {{ current_timestamp() }}                              AS computed_at
FROM {{ prev }}
ORDER BY annee, mois, region

    6. foreach_query — un rapport par région

    rapport_region:
  sql: sql/regional/rapport_region.sql
  target: "{{ params.schema }}.rapport_{{ region }}"
  write_mode: replace
  foreach_query: >
    SELECT DISTINCT region FROM commandes ORDER BY region
  foreach_parallel: true
  foreach_workers: 4
  foreach_on_error: skip
  after: [commandes]

    La requête foreach_query retourne une ligne par région. Noria lance une exécution par ligne, en injectant {{ region }} dans le SQL et dans le target:.

    -- sql/regional/rapport_region.sql
-- {{ region }} injecté depuis foreach_query — ex : 'IDF', 'ARA', 'OCC', 'HDF'
SELECT
    '{{ region }}'                                       AS region,
    c.id_client,
    cl.nom_complet,
    COUNT(c.id_commande)                                 AS nb_commandes,
    ROUND(SUM(c.montant), 2)                             AS ca_total,
    {{ rank_by(by='region', order_by='SUM(c.montant) DESC') }} AS rang_region,
    {{ current_timestamp() }}                            AS computed_at
FROM commandes c
LEFT JOIN clients cl ON c.id_client = cl.id_client
WHERE c.region = '{{ region }}'
  AND EXTRACT(YEAR FROM c.date_commande) = {{ params.annee }}
GROUP BY c.id_client, cl.nom_complet, cl.ville
ORDER BY ca_total DESC

    7. KPI globaux — safe_replace

    kpi_global:
  write_mode: safe_replace
  safe_replace_min_rows: 1   # avorte si le SELECT retourne 0 lignes
  after: [stats_mensuelles]

    -- sql/kpi/kpi_global.sql — schemas: qualifie commandes
SELECT
    {{ params.annee }}                                                AS annee,
    COUNT(DISTINCT id_client)                                         AS nb_clients_actifs,
    COUNT(*)                                                          AS nb_commandes,
    ROUND(SUM(montant), 2)                                            AS ca_total,
    ROUND(SUM(montant) / NULLIF(COUNT(DISTINCT id_client), 0), 2)    AS ca_par_client,
    {{ current_timestamp() }}                                         AS computed_at
FROM commandes
WHERE EXTRACT(YEAR FROM date_commande) = {{ params.annee }}

    8. Assertions qualité

    verif_clients_email:
  type: assert
  sql: sql/assert/assert_clients_email.sql
  after: [clients]

verif_commandes_montant:
  type: assert
  sql: sql/assert/assert_commandes_montant.sql
  soft_fail: true     # warning seulement, ne bloque pas le pipeline
  after: [commandes]

    -- sql/assert/assert_clients_email.sql — doit retourner 0 ligne
-- schemas: qualifie clients
SELECT id_client, nom FROM clients WHERE email IS NULL OR TRIM(email) = ''

    Lancer la démo

    cd examples/demo

# Exécution complète
noria run

# Compiler le SQL sans exécuter
noria run --dry-run

# Voir un job spécifique
noria preview stats_mensuelles

# Seulement les jobs core
noria run --only-tags daily

# DAG dans le navigateur
noria dag
